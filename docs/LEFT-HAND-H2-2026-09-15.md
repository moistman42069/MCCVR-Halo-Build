# Halo 2 opt-in anatomical palm alignment

The user reports that left-handed `Fix Hand Alignment` puts the hands to the
right of the actual gun. This correction is limited to that existing opt-in
presentation transaction. Normal right-handed and default-off placement retain
the accepted `7ff9697` path. The Halo 3 player behavior being matched is that the
anatomical main hand grips the actual primary weapon and the support hand keeps
its solved support grip, including independently held dual weapons.

## Observed source defect

`Halo2RouteLeftHandedPacketHands` ran after native hands and gun packets had
already been moved into their final controller roles. It applied another
controller-frame rotation and placed each anatomical wrist at the opposite
wrist's origin. A wrist origin is not the semantic palm/grip marker. The
accepted `Halo2BuildCorrectedRigMarkerFreeLeftTarget` already accounts for the
left palm marker when solving the normal role-based hand. Exchanging only wrist
origins discards this distinction and also ignores the final gun-relative grip
orientation already present in the solved wrists.

The official Chief model's marker Y coordinates differ by 0.020077 native
units, about 6.12 cm with world scale 3.048. This is a concrete authored lateral
offset omitted by wrist coincidence; the exact error for a posed frame also
depends on its wrist rotations and scales. No headset measurement is inferred
from this number.

Both `Halo2VisibleFirstPersonConsumerDetour` (Anniversary) and the Classic final
packet builder in `halo2_observer_6dof.cpp` call the same single/dual ownership
helpers. The optional route is downstream of the primary and secondary gun
solves in both helpers. No renderer hook, signature, controller role, or gun
matrix calculation changes here.

The export has no Dervish right-hand marker. This is not filled by copying a
Chief, CE, or Halo 3 offset. Dervish's own left/right wrist local rotations are
identity, with the same local X translation 0.108930. Its paired digit-base
translations establish the anatomical local-Y reflection plane: index bases
are (0.044999, +/-0.010830, 0.008621); pinky bases are
(0.013546, -/+0.000770, -0.008559). Ring/thumb bases follow that plane with
small authored asymmetries. These are geometric evidence for the plane, not
evidence of an unexported native right marker or identical digit rotations.

For Elite only, the VR presentation deliberately derives the missing right
semantic marker from its own left marker with `F = diag(1,-1,1)`:
`right.position = F * left.position`,
`right.rotation = F * left.rotation * F`.
This gives a proper rotation and a bilateral grip convention. It remains a
VR-side implementation difference requiring headset validation. The cold
hand-binding installation log states native Chief versus derived Elite use.

Native marker metadata exports a zero scale. As in the accepted C-H2-70
semantic marker solve, these local marker frames use unit scale; wrist/hand
scale is carried by the final solved packet. The existing engine evidence for
packet ownership, rig selection and remaps remains E-H2-40/45 in the H2
evidence documents.

## Final-packet arm-chain evidence (2026-09-30)

The same official H2EK first-person render-model exports establish a verified
two-joint arm chain for both shipped rigs. Chief nodes are `base` 0,
`l_upperarm` 1, `l_forearm` 3, `l_hand` 5 and the mirrored right-side nodes 2,
4, 6. Elite uses the same named parent topology at the same render-model node
indices. H2EK defaults place the shoulder-to-elbow offsets at 0.093990 native
units and elbow-to-wrist at 0.102507 (Chief) / 0.102510 (Elite). These are
tag-authored default offsets, not assumed live lengths; runtime solves measure
each current root-composed final packet.

`out/left-hand-h2-evidence/chief-fp.xml` (SHA-256
`C840E9035AB3EEFE3FF3C5030961E121AADBB0688FF313CAD23BE59E860AFD01`) and

packet binding cross-checks the engine's right/left hand flags and derives its

solve therefore runs at the established final-packet boundary after native
animation and root composition; it does not revive the rejected interpolator
hook. Both arms and their wrists are staged together. If either fails, arm
records return to the previous hidden presentation while controller-owned
hands and gun still commit. The two-weapon dual-wield packet transaction does
not enable this solve and retains its prior behavior.

## Correction and verification scope

For each anatomical destination hand, compute the opposite already-solved
palm and invert the destination hand's own local marker:

```
targetPalm = oppositeSolvedWrist * oppositeLocalMarker
desiredWrist = targetPalm * inverse(ownLocalMarker)
subtreeDelta = desiredWrist * inverse(ownSolvedWrist)
```

Apply that delta to the existing proven anatomical subtree. This preserves the
actual solved grip, its complete orientation, and the destination weapon-role
scale. There is no controller-origin approximation, fixed translation, or
second controller mount rotation. The primary and secondary gun packets are
unchanged. Existing finite/count/remap checks, Elite hidden-arm handling and
staged atomic publication remain. Invalid marker/packet evidence rejects this
optional hand transaction without publishing a partially transformed palette.

`tests/left_hand_h2_tests.cpp` invokes the production final single/dual packet
helpers using Chief/Elite, distinct compose bases, engaged/free support,
unequal carrier poses, nonidentity wrist rotations and hand scales 0.5/1/2.
It compares full semantic palm transforms against the already-solved opposite
grip, requires gun packets to remain byte-identical, and checks destination
scale plus duplicate-map/late-invalid-node atomic rollback. Existing H2 core
assertions now require palm-frame coincidence instead of encoding the former
wrist-origin defect. These are offline transform regressions; neither renderer
nor either rig is claimed headset-accepted by these tests.

The dedicated H2 production packet suite builds and passes, recorded in
`out/left-hand-h2-tests.log`. The final cumulative build/test gate runs again
after all title changes are ready. Required user testing includes Chief/Elite single
and dual weapons in Classic/Anniversary, support grip, unchanged default-off
